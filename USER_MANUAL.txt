Antenna Surrogate Studio User Manual
====================================

Purpose
-------
Antenna Surrogate Studio helps users create local projects, import antenna simulation or measurement CSV data, configure model inputs and outputs, train XGBoost surrogate models, validate results, and make new predictions.


Sequential Workflow Rules
-------------------------
Antenna surrogate modeling steps are interlinked, so future workflow tabs remain disabled until prerequisites are complete. Users may go back to earlier tabs, but they cannot jump to diagnostics, training, validation, prediction, or model history before the required prior step has succeeded.

The app unlocks steps in this order: create/open project, import data, prepare a valid dataset, review diagnostics, train a model, validate and predict. Blocking data-validation errors must be fixed before the prepared dataset can be saved.

Library
-------
The Library page shows project cards for recent projects and built-in examples. Use New Project to create a folder under projects/. Use Open Existing Project to select a folder containing project.json. Use Import Project ZIP to restore a portable bundle.

Project Setup
-------------
Enter a project name, project type, description, optional antenna category, and units preference. The app sanitizes folder names and appends a timestamp if a folder already exists.

Import And Configure Data
-------------------------
Use Single wide CSV when design variables and outputs are in one file. Use Split input/output CSV when inputs and outputs are separate files joined by a sample ID. After loading columns, select at least one input column and one output column, then click Prepare Dataset.

The app checks for missing values, duplicate IDs, nonnumeric selected columns, constant inputs, duplicate samples, low sample counts, and large outliers. It does not silently repair the dataset.

Diagnostics
-----------
The Diagnostics page shows findings, sample counts, train/test estimates, summary statistics, duplicate sample count, and input correlation data.

Train Model
-----------
The Train Model page trains a multi-output XGBoost model in a background thread. Default settings are 100 estimators, max depth 6, learning rate 0.1, square-error objective, random seed 42, and 20 percent test split.

Every training run creates a new model version. The app saves the model, metadata, training report, metrics CSV, active model pointer, and package versions.

Validate Model
--------------
The Validation page displays overall RMSE, MAE, R2, per-output RMSE, per-output MAE, per-sample RMSE, 95th percentile sample RMSE, maximum error, training time, and train/test sample counts.

Predict
-------
The Predict page creates fields from the active model input schema. Values outside saved training bounds generate extrapolation warnings but do not block prediction. Batch prediction accepts a CSV containing the same input columns in the saved order.

Model History
-------------
Model History lists every trained version and lets you activate an older version. Older artifacts remain on disk. Do not delete active model files manually.

Assistant
---------
The Assistant page provides Basic Offline Guide answers from bundled documentation. It can explain screens, buttons, metrics, warnings, workflow steps, files, and common troubleshooting. It does not modify projects, train models, change settings, export files, access the internet, or provide antenna-design recommendations.


macOS Launch
------------
The application uses the same Python source code on macOS and Windows. Windows uses setup_windows.bat and run_app.bat. macOS uses setup_mac.sh and run_app.command. Both create a local .venv, install requirements.txt, and run app.py.

On macOS, install Python 3.10 or newer first. If double-clicking setup_mac.sh does not open Terminal, right-click it, choose Open With, and select Terminal. After setup, double-click run_app.command.

Troubleshooting
---------------
If import fails, check CSV encoding, duplicate columns, sample ID consistency, and numeric selected columns. If training fails, verify dependencies were installed by setup_windows.bat. If a model cannot load, preserve the project files and review the metadata package versions.
